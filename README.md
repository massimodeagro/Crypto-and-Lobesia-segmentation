# Lobesia and Crypto finder tool
This repository contains the code, weights and metadata for the trained YOLO model described in the paper IN PREP. The system is capable of recognizing and counting insects attached to sticky traps using [Ultralytics YOLO](https://docs.ultralytics.com/it/) . It is specifically designed to recognize Crypto and Lobesia, and distinguish them from other insects stuck on the traps.

This readme describes the process we followed to train and test the model.

The model was trained and evaluated with Python 3.12.7, PyTorch 2.5.1 (CUDA 12.4), ultralytics 8.3.91 and sahi 0.11.22.

## Training

### Preparation of training data
To start, traps needed to be manually segmented to recognize the presence of the species you want to identify.
Segmentation of the pictures was to be done with a standalone software. We used [coco annotator](https://github.com/jsbroks/coco-annotator) for this project, but any other may work. The data was then exported in COCO format. The coco format contains the annotation information into a standardized json file, together with a folder containing all the images.

### Dataset
The annotated dataset used to train and test the model is included in the `dataset` folder, in COCO format:
- `dataset/Images/`: the 64 trap pictures (one per trap, about 2400×3400 or 4800×6900 pixels);
- `dataset/Traps.json`: the 6595 segmentation annotations (polygons), divided in three classes: *L. botrana* (`Lobesia`, 773), *C. gnidiella* (`Crypto`, 3187) and other insects (`Other`, 2635).

### Slicing the images
Recognizing the different insects require the resolution to be quite high, as the details are needed to distinguish different species. However most computers will be unable to analyze the images at full resolution as wholes, without any rescaling. For this reason, in this project we decided to use the [sahi](https://github.com/obss/sahi) tool. This was used for both training and then for images segmentation. The script `sliceCoco.py` was used to split images in partially overlapping sections.

### Converting to YOLO format
Before proceeding with training, the dataset was be converted to Ultralytics YOLO standard using `coco2yolo.py` script. The pictures have then been moved manually to the newly created folder. Then, we generated the training/validation split files using the `fillDatasetTXT.py` script.

### Splitting the dataset by trap
The training, validation and test split files, together with `data.yaml`, are generated by the `fillDatasetTXT.py` script. Data is split by trap, rather than by slice, to prevent overlapping sections to be both in training and validation data, which may prevent generalization of the model. Moreover, we kept out 4 traps to act as a never-seen-before test. The remaining 60 traps were divided 90/10 between training and validation.

### Training
The model was then trained using the `ModelTraining.py` script. Augmentations are listed in `metadata/train_params.yaml`.

## Evaluation
The `evaluateModel.py` script computes per-class precision, recall, F1-score and mAP:
- at slice level, on the validation and on the test slices;
- at trap level: whole pictures are scored using SAHI (box IoU ≥ 0.5). The confidence threshold is first chosen on the 6 validation traps, as the one (between 0.3 and 0.8) giving the highest mean F1-score of *L. botrana* and *C. gnidiella* (`threshold_sweep.csv`). The 4 held-out traps are then scored once at that threshold (0.6 as discovered by thre sweep). The script also reports the confusion matrix and the true vs predicted count of each class per trap.

The results are in the `metadata/evaluation` folder.

## Usage
The script `predict_sahiSlice.py` (treshold set as 0.6, as per evaluation) generate videos showing the incrementing count of detected targets. This is of course just an example, as the data can be used in many other ways.

## Model and metadata
the model weights are included in the `model` folder, and the annotated dataset in the `dataset` folder. The metadata instead are contained in the `metadata` subfolder, and include the training parameters, the training metrics, the model architecture.
